One request, three steps.

Pocket Approve polls the OpenCode servers you configure. It does not replace OpenCode or run the agent. It just moves the permission prompt to a device you already have.

  1. 1

    OpenCode asks

    A tool needs permission. The request includes the tool name, the command, and the project directory.

  2. 2

    Your phone rings

    The request arrives through ntfy or Web Push. On Linux, the desktop gets the same notification.

  3. 3

    You decide

    Approve once, approve for the session, or deny. Pocket Approve sends the decision back to the original request.

Pick the path that fits your network.

Both paths use the same approval flow. The difference is how the notification reaches the phone.

Browserless

ntfy relay

Run npm run connect, scan one QR code, and receive requests in the ntfy app. Works on Android and iOS. The topic acts as a secret and the action links are signed.

  • No service worker or CA install
  • Use ntfy.sh or a self-hosted ntfy server
  • ntfy.sh can read the message body, so self-host for sensitive commands
Local only

Web Push

Run the Pocket Approve server on your LAN and install the PWA on your phone. Requests arrive through Web Push, with no public relay in the path.

  • Needs a one-time local CA install
  • Works with an installable PWA, including iOS Home Screen apps
  • Keeps prompts and commands on your network

Approval is never silent.

The service is designed around explicit decisions, short-lived pairing, and local ownership of state.

  • Short-lived pairing. Codes expire after 10 minutes and allow five attempts. A used code cannot be replayed.
  • Hashed device tokens. Each device gets a 32-byte token. Only a SHA-256 hash is stored, and comparisons are constant time.
  • Constrained API. Exact origin checks, rate limits, bounded request bodies, and a fixed static file map.
  • Honest about the relay. ntfy.sh can read notification content. Use a self-hosted ntfy server or the local Web Push path when the command text is sensitive.
  • No inferred approval. A closed notification or a failed action never becomes a decision. A reply must match the request.

Start in a minute.

You need Node 20 or newer, an OpenCode server, and a phone. The browserless path is the shortest setup.

Read the full setup guide for multi-server configuration, TLS, pairing, and the security model.

ntfy relay

git clone https://github.com/engida32/pocket-approve.git
cd pocket-approve/pocket-approve
npm ci
npm run connect

local Web Push

npm run setup -- --mode lan --host 192.168.1.20
npm start
npm run pair -- --label "My phone"

After npm start, open http://192.168.1.20:8081 to install the local CA, then open https://192.168.1.20:8443 and enter the pairing code. The ntfy path needs no certificate or local network route.
